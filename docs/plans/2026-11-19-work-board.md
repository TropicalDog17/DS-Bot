# 工作看板

- 日期：2026-11-19
- 相关：取代 [群聊任务面板](2026-11-12-group-task-board.md) 的数据和工具

## 为什么

用户的活不只在群里：Bot 在自己的聊天、两个 Bot 的对话里也会接活，`group_task` 出了群就不能用，用户得一个群一个群地翻。工作看板是整个团队一份：谁在做什么、卡在哪、等用户看什么，打开一页就知道。

## 已定的行为

- 看板属于整个团队，存在 `state.board.cards`，随 `state.json` 经 `rt.load` / `rt.save` 保存。
- 五列：Todo（`todo`）、In progress（`active`）、Review（`review`）、Blocked（`blocked`）、Done（`done`）。Done 只显示最近 7 天内、最多 10 张，其余和已取消（`cancelled`）的卡收进 History；取消不是一列。
- 卡片字段：一行标题（200 字）、可选工单号（Jira 式 `LIFE-782`，存大写）和 http(s) 链接、负责人（某个 Bot 或用户 `user`）、开卡者、最新进展（300 字）、链接列表（PR 等，最多 20 条，去重）、备注、结果（2000 字）或取消原因（500 字）、所在群（从群里开的卡）、创建 / 更新 / 完成时间。
- Bot 用工具 `board`，任何会话都能用（自己的聊天、群、Bot 之间的对话）：`open` 接活时开卡（默认 In progress、负责人是自己，可以写别的 Bot 的准确名字或 `user`）、`update` 改状态 / 进展 / 加链接、`complete` 带一句结果完成、`cancel` 带原因取消、`show` 看整个看板。不写 `id` 时指自己最新的未完成卡；`id` 也可以写工单号。
- 校验严格：工具 schema 先拒绝未知动作、状态和非文本参数；工单号和链接格式不对、标题为空、未完成的卡里已有同一工单号时直接拒绝并说明。
- 负责人、开卡的 Bot 和 Main Bot 能改卡；取消另外允许卡所在群的管理员。完成和取消是终态，Bot 不能再改。
- 用户在看板页：加卡（标题、工单号、链接、负责人），桌面上拖到另一列，手机上打开卡片点列名移动（看得见的按钮，不靠手势）；打开卡片看进展、链接、备注，加备注，取消。用户可以把卡移到任意列，包括移出 Done。
- 备注送到负责的 Bot：从群里开的卡、且这个 Bot 仍在群里，以用户消息 `@Bot 备注` 发进群；否则发到这个 Bot 自己的聊天，带上卡号和标题。负责人是用户的卡只记备注。从界面加卡不通知 Bot，Bot 用 `board show` 看到。
- 入口：侧栏顶部的看板按钮，宽侧栏和窄栏（手机）都有，一次点击打开。手机上看板占满屏，列变成顶部的标签，默认打开最需要用户的一列（Review，其次 Blocked）。
- 群详情抽屉里的任务面板继续存在，列出这个群开的卡。
- 迁移：旧数据里每个群的 `room.tasks` 在加载时搬进看板，保留 id、状态、进展、备注、结果和所在群，然后删除 `room.tasks`；只搬一次。

## 不做什么

- 不按群分看板，不做工时、截止日期、优先级、子任务。
- 不和 Jira 同步，工单号只是标签和链接。
- 不从聊天消息里猜卡片。

## 已知限制

- 历史不自动删除，卡片会一直留在 `state.json` 里。
- 拖拽用 HTML5 拖放，只在桌面浏览器里有效；触屏用卡片里的移动按钮。
