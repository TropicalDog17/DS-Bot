# IM: talk to Bots in chat apps

- Date: 2026-11-04
- Related: #904; [group chat](2026-10-07-group-chat.md),
  [browser, search, secrets and connectors](2026-10-08-browser-and-secrets.md),
  [mobile app](2026-10-24-mobile-app.md)

## Why

When the user is away from the computer, the Bots keep working, but the user can only reach them by
going back to DS Bot. Most people keep a chat app such as WeChat, Feishu or Telegram open all day.
IM lets the user talk to a Bot or a group there: messages go into the Bot or the group, and the
Bot's replies and cards go back to the chat app.

Trade-offs:

- **IM is a channel, not a member.** A bot in the chat app (below: an "IM bot") is bound to one Bot.
  It is not on the Bot roster and has no role or rights of its own. What the user says in IM is the
  user's own words and goes into the Bot's current part, the same as typing in DS Bot.
- **DS Bot builds it itself.** The connection, the binding, what gets sent and the settings page all
  belong to DS Bot. Messages go straight into Bots and groups, not through DSH's own Sessions. The
  plugin and the desktop app use the same code. Part of the protocol code for each platform comes
  from MIT-licensed open-source implementations; see `NOTICE`.
- **The computer only connects outward.** Only the platforms' long-connection or long-polling
  interfaces are used: no public IP and no open ports are needed.

## Decided behavior

### Platforms

| Platform | Connection | What to fill in | Private chat | Group | How cards are answered |
|---|---|---|---|---|---|
| WeChat | Tencent iLink, bind by QR code, long polling | Scan the QR code | Only with the account that scanned | Not supported | Reply with the number |
| Feishu / Lark | Long connection | App ID, App Secret; choose Feishu or Lark | ✓ | @ the bot | Card buttons |
| DingTalk | Stream mode | Client ID, Client Secret | ✓ | @ the bot | Reply with the number |
| WeCom | Smart bot long connection | Bot ID, Secret | ✓ | @ the bot | Card buttons |
| QQ | Official bot Gateway | App ID, App Secret | ✓ | @ the bot | Reply with the number |
| Telegram | Bot API long polling | Bot token | ✓ | @ the bot or reply to it | Buttons |
| Discord | Gateway | Bot token | ✓ | @ the bot | Buttons |
| Slack | Socket Mode | App token, Bot token | ✓ | @ the bot | Buttons |

### Adding and binding

- Settings → "IM" lists the IM bots added so far, one row each: platform, account name, state
  (connected / connecting / cannot connect, with the reason) and the bound Bot.
- Adding: choose the platform, fill in the fields from the table (scan the QR code for WeChat), and
  choose the Bot to bind. DS Bot checks with the platform once and saves only if the check passes.
- One IM bot is bound to one Bot: all private chats go to this Bot. Changing the binding, disabling
  and removing are all in this row.
- Platform credentials are stored in DS Bot's secrets (visible in Settings → Secrets) and are not
  given to any Bot; they are replaced as usual before anything is sent to the model. Removing the IM
  bot deletes them too.
- Groups of the IM bot in the chat app: the first time a paired account `@`s it in a group, this
  group shows up in its row, and the user picks a DS Bot group for it (or a Bot). Until one is
  picked, the IM bot replies in the group that the group is not bound yet.
- When the bound Bot or group is deleted, the private chat or group goes back to "not bound yet".

### Pairing: only accounts that were allowed

- The first time an account messages the IM bot (in a private chat, or by `@`ing it in a group),
  Settings → "IM" shows "Who wants to connect" with the account's name on the platform. Pairing
  happens only when the user clicks "Allow"; "Deny" removes the request.
- An account that is not paired: its messages go into no Bot, and the IM bot replies once that a
  connection request was sent. Buttons also count only for paired accounts.
- The WeChat account that scanned the QR code is paired automatically: the scan itself is the
  confirmation on the computer.
- A paired account can be removed in the settings; after that its messages no longer go into the
  Bot.

### How messages travel

- Private chat: the message goes into the bound Bot's current part and queues like a message sent in
  DS Bot (if the Bot is busy, it waits for the turn to finish). The chat history marks which
  platform the message came from.
- Group: the message that `@`s the IM bot goes into the bound DS Bot group with the `@` removed, the
  same as the user speaking in the group.
- Images go to the Bot as images, files as attachments. When the platform provides a voice
  transcript, the transcript text is sent; otherwise the voice message is sent as a file.
- While the Bot is busy, platforms that support it show "typing".
- `/stop`: stops the work of the bound Bot (or of all members in a group).

### What goes back to the chat app

- A reply goes only to the IM connection and conversation that sent the message that started this
  turn; other chats bound to the same Bot do not receive it.
- Messages from the web page, the mobile app, other Bots, scheduled tasks and turns with an unknown
  source are not sent out to IM.
- Once another source is mixed into the same turn, nothing more goes out to IM; later messages
  cannot claim a mixed turn back.
- Group members' replies follow the source that started this round of group work; system notices
  and event lines are not sent.
- Questions, approvals, secret prompts and view cards follow the same source rule. When a question
  card is answered through IM, the follow-up goes back to that IM conversation along with the
  accepted card answer; cards answered on the web page or the phone do not inherit the IM source.
- Replies are sent in the platform's format; ones longer than the platform's single-message limit
  are split into several and sent in order.

### Cards

- **Question card**: sends the question and the options. Platforms with buttons use buttons; others
  reply with the number (several numbers separated by spaces for multiple choice). Once answered on
  any side, the card stops working everywhere else; platforms that can edit messages replace the
  buttons with the answer.
- **Approval**: approvals from the Bot's own chat and from members in groups are both sent. Buttons
  or numbers: 1 Allow once, 2 Reject. Whichever of the approval card in DS Bot and the one in IM is
  answered first counts, and the other stops working at once.
- **Secret card**: not filled in inside the chat app (the value would stay on the platform's
  servers). IM only says which Bot needs which secret and asks the user to fill it in on the
  computer or in the mobile app.
- **View card**: sent as text; for a view that needs a reply, the user is asked to reply on the
  computer or in the mobile app.
- A number answers only the latest card still open in this chat; at other times a number is just an
  ordinary message.

### Running

- Only the dsh that holds the team lock connects to IM. A read-only window does not connect; it
  connects after it takes over the lock. So each reply is sent only once.
- A dropped connection reconnects on its own, with growing intervals; the state and the latest error
  show in the row.
- Send failures: what the platform clearly refuses (expired credentials, past the platform's reply
  window or quota) is not resent and shows in the row. What was not sent (no network) is sent in
  order once the connection is back. When it is unclear whether something was sent, it is not
  resent, so that the same message is not sent twice.
- Cards already sent are recorded in the data folder and are not sent again after a restart.

## Not done

- IM bots do not join the Bot roster, do not hand out work and do not act as outside workers (that
  belongs to "local agent CLIs as Bots").
- People who are not paired cannot talk to Bots; what other people say in a group is not passed to
  Bots.
- No filling in secrets, managing the team or changing settings from the chat app.
- No interfaces that need a public callback address, and no platforms with unofficial protocols.

## Known limits

- WeChat and QQ only allow replies for a while after the user sends a message, and the platform sets
  the quota; replies after that cannot be sent. The settings show why, and sending one more message
  restores it.
- WeChat can only chat privately with the account that scanned the QR code, and does not support
  groups.
- DingTalk, QQ and WeChat have no card buttons, so cards are answered with numbers.
- While the computer is off or asleep, messages wait if the platform keeps them; messages the
  platform does not keep are lost.
- The mobile app has no IM settings page yet.
- In a Bot's private chat, DSH draws the user messages of the current part, so they do not show
  "via …" yet; group chats and earlier parts do show it.

## Changes

- 2026-11-13: IM now replies only to the source conversation; nothing goes out for mixed or unknown
  sources.
